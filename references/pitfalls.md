# Common pitfalls (problem -> fix)

1. Mix judged by meters only, never heard -> say so in the report; ask the user to listen once on speakers and tell us what to change (kick and bass 1 to 2 dB down was the typical fix).
2. Bass-heavy synthesized groove, most energy under 120 Hz -> high-pass the master slightly, lower kick and bass, add brighter keys.
3. Music is a short loop with no arc (LRA 0.9 to 2.7 LU) -> add a build, a drop-out of one 16th note before the drop, an end chord; do not rely on level changes after normalising.
4. Limiter squashes hits when the mix is pushed to -14 LUFS (up to 9 or 10 dB on the biggest impacts) -> lower the stacked kick, stab and clap gains before the limiter, then master; Q805 fails a master whose limiter took over 0.5 LU or over 6 dB at one moment, and names that moment.
5. Final chord or end hit is much louder than the average (about -11 LUFS short-term against -14 integrated) -> lower the last chord a few dB, or accept and tell the user.
6. Reverb impulse not normalised, so the mix turned into reverb -> normalise the impulse response and check wet/dry level.
7. First frame nearly black or an empty paper frame, so the thumbnail is weak -> draw the hook at t=0 and export a separate poster PNG.
8. Empty frame at the start of each scene (lead silence, 0.3 to 0.4 s) that reads as a cut to black -> start the next scene's picture before the previous one ends, or trim the lead silence in the audio.
9. Text too small: 14 to 26 px labels are unreadable on a phone -> keep key lines at 36 px or more; treat smaller type as decoration only.
10. Text on screen for only 1 to 2.5 s because late-appearing body lines get the short end of a scene -> bring the body line in earlier, or extend the scene, using the reading-hold rule (`qa-gates.md` gate 4).
11. Too many items per second (2 s per chapter, 0.75 s for key lines) -> fewer items per video or a longer cut; a 15 s brief with many milestones needs about 20 to 24 s to read well.
12. Brand colour fails contrast (cream on coral badge at 2.6:1; small coral or mint text) -> use a darker tint for small text and report the deviation.
13. Difference blend mode on a HUD turns cyan on red and low contrast -> no blend modes on readable text.
14. Strobe-like passages (background flipping 4 to 5 times per second, full-frame accent wipes held 4 frames, inverted impact frames) -> run the flash test (`qa-gates.md` gate 6, `qa.flash_window` over the passage), reduce, and warn. A sprite blinking white on four hits within one second fails even when the sprite is small; one dip to white is one flash.
15. Fast moves look steppy or strobe at 30 fps (zoom from scale 1 to 34 in 0.7 s, scrolls near 1,200 px/s) -> add motion blur (average 3 to 5 sub-frames per frame), slow the move, or render 60 fps if the size limit allows.
16. Mid-transition stills look broken (letters as slivers, half-masked words, translucent stacked cards, mid-flip warping) -> accepted only if 1 to 3 frames; check them in the contact sheet and fix any that stay over 0.3 s.
17. Cards or elements overlapping on hold frames (a label over a flag, call-stack HUD over layout, a title crossfade over a fading header) -> use the overlap test (`qa-gates.md` gate 2) and move elements or stagger the exit.
18. Fonts fall back to a system font when the file is rendered elsewhere -> use fonts found on the device (list C:/Windows/Fonts on Windows, /System/Library/Fonts and /Library/Fonts on a Mac), load by absolute path, and fail loudly if a font is missing.
19. Hand-built maps or sprites look rough (coarse land mask, blocky figures, crude letters) -> say it is a schematic in a note on screen; do not call it accurate.
20. Stale facts (review counts, prices, rankings) -> put the date on screen and in the report ("as of ..."), or leave the number out.
21. A simplified story presented as one real session (a git or code walkthrough that jumps between states) -> add a line like "a little later" or a note that it is simplified.
22. Text-to-speech mispronounces names and acronyms (a short word read as "it", brand names, years) -> spell it phonetically in the voice text, keep the on-screen text correct, and ask the user to listen to those lines.
23. Voice speed differs between voices -> measure each line's real length before fixing the schedule; do not assume one speed.
24. Footage or photos upscaled from low resolution look soft at 1080p -> use only for a deliberate archive look (add grain, duotone) or ask for a better file.
25. Footage with third-party signage or logos visible -> crop or blur, or tell the user; we do not show third-party logos.
26. Several seconds of a scene go sparse after a big effect (a shockwave that clears the stage by 6.5 s of an 8 s story) -> shorten that scene or add a second beat.
27. Audio and caption sync only approximate because shots were chosen from low-resolution previews -> check at least 40 frames against the script lines and fix the ones that show the wrong thing.
28. Large files for short videos (grain, halftone, petals, paper texture; 56.8 MB for 46 s, 15.8 Mbps) -> CRF 20, no grain, or 720p when the destination has a limit.
29. Render stopped by low disk space -> check free space first (`shutil.disk_usage`), delete intermediate PNG frames (only `--keep-frames` writes them) and raw WAV once the file is verified, and say what was removed.
30. Layout drift in a still between sampled frames (cursor blink shows off at some times) -> this is correct motion, not a bug; do not "fix" it.
31. Session ended before the final QA -> run the gates in `qa-gates.md` anyway after the build; never report "checked" for something we did not run.
32. A claim in the report that is not backed by a tool result ("looks great", "plays everywhere") -> write only what we measured, and mark the rest unverified.
33. Two strings crossfading in the same spot read as garbage for 10 to 15 frames ("h =>0.001") -> fade the old one out, then the new one in; Q203 catches it from the registry.
34. A fix or an optional tweak made after a REVIEW PASS breaks something next to it (a damage plate moved onto the hero; a line-height change hid a counted outline under a header) -> list every post-PASS change with its times, run `qa.py diff --expect <those windows>` (it names every frame that changed, declared or not) and review those frames and their neighbours again.
35. The AAC encode adds true peak: up to 1.23 dB at 192k and 0.45 dB at 320k over 9 mixes (2026-10-28) -> master at -2.0 dBTP with the true-peak limiter (`audio.master` default) and mux AAC at 320k; `run_all.py` re-masters when the mp4 reads over -1.3, and Q802 names every sound at the loudest moment.
36. Storyboard slots shorter than the reading time force the builder to re-time captions (27 of 83 lines in one batch; 28 under the 2.2.0 rule) -> run `qa.py holds` on the scenario before any build.
37. A string's `hash()` seeds a different picture in every process: str hashes are salted per process, so each render worker drew other lightning in the g29 kit (`scenes.py:670`, 23,940 px off at 32.07 s) -> seed from `zlib.crc32(s.encode())` or `engine.rng(...)`; `qa.py lint` flags `hash()` as Q1202.
38. A counter, list or cache written inside draw(t) makes a frame depend on what was drawn before it (a background cached by scene kind kept the first frame's drift) -> compute it from t, or key the cache by everything it depends on; Q1201 names the frame that poisons it, Q1203 the line.
39. Iterating a set of strings draws in a different order in every process -> `sorted()` it, or use a list or a dict; only the fresh-process pass of Q1201 sees it on one machine.
40. A draw that needs state an earlier frame left behind (a dict the first scene fills) raises or changes when frames are drawn out of order, as render workers draw them -> build it at import or derive it from t; Q1201 reports the reversed pass raising.
41. A redirected Windows console is cp1252: printing a caption with an arrow raised UnicodeEncodeError and rejected a build whose gates all passed -> print rows through `contract.line` (ASCII, other characters as `\u` escapes); qa.py and run_all.py already reconfigure stdout and stderr.
42. Raw 1080p frames (6.2 MB each) sent back from render workers through a process pipe died with WinError 1450 when several builds shared the machine (7 of 45 renders at five builds of 5 processes) -> the shared-memory ring in render.py passes only digests and thumbs (0 of 40); never return frames from a pool.
43. An ffmpeg decode without `-nostdin` stops early with exit code 0 when a key waits on stdin (a piped "q" cut a 60 s check to 200 of 1800 frames, and a voice decode of 1800 s to 157 s) -> pass `-nostdin`, close stdin and check the decoded frame count, as every engine decode does.
44. A duration typed as a quotient is not exact: read through their shortest repr, n / 30 s transitions came out 4, 8, 10 and 14 frames for n = 5, 7, 11, 13 -> `compile_schedule` reads floats as fractions with a denominator up to 10**6; elsewhere count frames with `frame_of`, never `int(t * fps)`.
45. Python's `round()` rounds halves to even, so two modules counted different frames (3.35 s at 30 fps: 100 by `round`, 101 by render.py) -> one rule everywhere: `contract.frame_of` (nearest frame, halves up).
46. Float seconds summed beat by beat open scenes a frame late (at 72 BPM and 24 fps, 128 of 400 one-beat scenes with `i * beat`, 237 with a running sum) -> declare the scenes in beats and let `compile_schedule` round each instant once.
47. A slow attack placed by its first sample is heard late (synth.pad's 0.25 s attack reaches -15 dB 44 ms in; the first batch's 37 to 87 ms of SFX lateness was mostly this) -> place pads and chords with `align='pad'`; Q902 holds a sound placed by its start to its audible attack.
48. A whoosh with its apex on the hit it leads stacks onto it (+1.8 dB of true peak on the template) -> lead it by 80 ms (`offset=-0.08`); Q804 counts a lead-in that lands on its heavy sound as one gesture.
49. One RandomState shared by a whole score: one sound more changed every later sound (6 of 6); and once each generator seeds from its arguments, round-robin copies with the same arguments come out identical (g04's four hats) -> seed each sound from its own name and arguments (`synth.noise`, `synth.rng_for`, one `seed=` per copy).
50. The AAC encode makes the two channels of a dual-mono mix differ (up to 0.66 apart), so a peak search on their mean named a moment seconds away from the real one -> read the true peak channel by channel, as Q802 does.
51. ffmpeg's `-ac 1` reads a dual-mono mix 3.01 dB hot, and `-ac 2` reads a mono file 3.01 dB low per channel -> average the channels yourself and read mono as mono (`contract.Ctx.audio`).
52. An untagged encode plays up to 40 levels off on saturated green when a player reads it as HD (BT.709) -> encode through `contract.COLOR_VF` and `COLOR_FLAGS`; Q707 checks the tags.
53. ffmpeg's default scaler truncates, so a decode read a dark end card 1 to 2 levels low and flipped the template's Q502 to FIX -> decode with `contract.DECODE_709` (accurate_rnd, full_chroma_int).
54. A forked render worker kept ffmpeg's stdin open, so the encode never saw its end and hung -> spawn the workers (render.py does on every platform).
55. Holding film grain for 2 frames does not shrink the file under x264's MB-tree (std 2.6: 63.1 MB a minute against 43.8 new every frame) -> shrink grain by its cell size or its std (`grain.grain` 1 px tiles: 17.5 to 19.1 MB a minute against 34.8 for the g11 kit's 2 px cells, CRF 20), and add it after any whole-pixel weave so it stays put (`formats.md`).
56. A counter or clock registered as readable text gave one Q401 FIX per value (313 on the rectangle film) -> mark it `ticker=True`: only the value a run settles on needs a hold.
57. A 2-frame changeover gap passes Q207 but repeats a frame between two moves (Q1104), and a title kept out of a 0.4 s transition window leaves 13 empty frames (Q207) -> leave 1 frame, or 0.5 s or more.
58. A build that keeps its cues in `CUE` and has no `text_items(t)` (the g04 kit as shipped) gets Q902 and gates 2 to 4 NOT CHECKED, so `run_all.py full` rejects it -> name the cues `CUES` (or set `NO_CUES`) and add the registry (`kits/README.md`).
59. SAPI's word clock ran 1.378x fast at its default 22.05 kHz output -> the bridge writes 16 kHz; check any new engine's word clock with `voice.onset_offsets` on its first real narration.
60. powershell.exe returned exit code 2 after a clean SAPI run while an event subscription was still registered -> unregister the events before exit (the bridge does).
61. The raw mix is peak-normalised, so a hit 10 percent quieter rescaled every sample (all 75 blocks of the template differed by hash) -> `qa.py diff` takes one overall gain out before it compares audio blocks; read its gain line before calling a change global.

Every failed build appends its pattern here (problem -> fix, with the measured case). When the check is mechanical, also add a `qa.py lint` rule (`engine/qa_lint.py`) or a gate, and name the code that catches it.
